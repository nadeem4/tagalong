# Layout: file by file

Where each part of the repository lives, down to the file. `CLAUDE.md` keeps only the top-level map; this page holds the detail. The brain's module map with links is in [brain/README.md](brain/README.md).

- protocol/README.md: contract v1 between the Python brain and the bodies (source of truth)
- protocol/examples: sample frames shared by the TypeScript and Python tests
- protocol/ts: `@tagalong/contract`, zod schemas for contract v1
- brain/: the Python brain (uv project; `src/brain/protocol.py` holds the contract v3 pydantic types; `service.py` the logon service (scheduled task, launchd agent, systemd unit); `build_info.py` the brain's version and build id (sent in `hello`), `main.py` starts the websocket server (`server.py`) and keeps `brain.pid` (`lifecycle.py`, which `tagalong stop` uses), `identity.py` the self-signed certificate of the network listener, `devices.py` paired devices (`store/devices.py` their SQL, migration 0041), `pairing.py` one-time pair codes, `tagalong://pair` links, their QR and `build_pairing`, `discovery.py` the mDNS announcement and the LAN address, `device_tools.py` Home's device tools, `memory_mcp.py` the memory tools other AI tools may call (their tokens are `devices` rows of kind `mcp_client`, migration 0045), `memory_bridge.py` the `tagalong memory-mcp` stdio server such a tool starts (its link files live in `<TAGALONG_HOME>/memory-clients/`), `link.py` the dial a node and the bridge share (wss pinned to a fingerprint, the hello and request framing), `mcp_client_tools.py` Home's tools for them and Scout's `connect_ai_tool` and `ai_tool_howto`, `loopback.py` the loopback server of the experts' MCP bridge, `private_file.py` owner-only file writes, `local_token.py` the token for bodies on this PC, `auth.py` who a hello token belongs to, `config.py` reads its settings from the environment and `.env`, `models.py` the choosable Claude models and the saved choice, `bridges.py` starts and watches the WhatsApp bridge on Tagalong's own Node (off unless set up, restarts with growing waits, stops with the brain), `bodies.py` tracks connected bodies and their outboxes, `sessions.py` the one conversation, `know/` Scout getting to know the person (`facts.py` tag visibility, `status.py` a run's per-source status, `runner.py` the one run at a time behind `know_me_start`, saving each source as it finishes; its status frame `know_me_status` goes out live; `portrait.py` the portrait written from free facts only, `offer.py` when Scout may offer, `tools.py` `get_to_know_me` and `rewrite_portrait`; `source.py` the source protocol and `default_sources`, `github.py`, `linkedin.py` (PDF text via pypdf) and `web.py` the sources, `extract.py` facts kept only with verbatim evidence, prompts in `mind/know_*.md`; see docs/data/memory.md), `memory.py` the `Memory` object over `tagalong.db` (it masks memory text on save), `store/` the only code that runs SQL (`db.py` opens `tagalong.db` and runs the numbered migrations in `store/migrations/`, `search.py` the FTS5 helpers, `conversation.py`, `memory.py`, `connections.py` and `outputs.py` the SQL of chat, memory items and layers, apps and tool outputs, `events.py` the events table (the one durable queue every input is saved to first), `work.py` the work tables, their state machine and the sweep of finished work, `rules.py` tool modes, preferences and offers, `settings.py` the chosen Scout model, `open_items.py` the open-item rows), `events_tools.py` Home's `events_waiting` (news still `new`, and news given up), `chat_tools.py` Home's `chat_since` (the saved chat after an id, for a body catching up after a resync), `tools.py` the brain's own tools, `tool_words.py` the plain title, line, info and group of every tool for Home's Permissions, `toolbox.py` the tool gate, `apps.py`, `app_oauth.py` and `app_tools.py` connected apps (MCP), their browser sign-in and their tools, `placements.py` where an app runs (the five modes, migration 0042; `store/placements.py` its SQL), `pipes.py` MCP over a node pipe, `placement_tools.py` Home's placement tools, `asks.py` permission asks, `holds.py` an expert's permission request or question held on a card with no timeout, `permission.py` the one engine for every ask (the floor, then rule, Scout, person), `open_item_runner.py` Scout's asks as open items (a turn never waits for a card; a later answer runs the saved call; deadline, restart and return), `approvals.py` the log of how each ask ended, `experts.py` expert adapters over ACP, one process per expert shared by sessions, `expert_apps.py` the loopback MCP bridge by which an expert reaches chosen apps through the toolbox, `jobs.py` the hand-offs to Claude Code, `job_records.py` jobs and their parts as goal and expert_call work rows, `job_activity.py` a job's steps as a masked, capped log, `reading.py` and `reading_tools.py` how the body reads the screen, kept for Home and Scout, `outputs.py` a long tool result as a capped preview with the rest stored masked for `read_output`, `side_check.py` Scout approving an ask under a preference, `open_items.py` the one record and lifecycle of what waits on the person, `telemetry.py` the loop-lag alarm and step timings (`timed`, `TIMINGS`), `offers.py` Scout offering a preference, `guardrails.py` the budget (searches included), `retry.py` which failures and tools may be tried again, `web_tools.py` Scout's web search and fetch (Anthropic's server tools), `guards.py` the guard runner, `masking.py` the Masker, save guard and log filter (secrets become `[secret]` before they are saved), `builtin_guards.py` the built-in guards, `tasks.py` the tasks (an Ask per say, settled when its turn ends; `store/tasks.py` the SQL) and the open-tasks block in the prompt, `task_tools.py` Scout's `task_start` and `task_end` and Home's `task_stop`, `tasks_tools.py` Home's `tasks_list`, `events.py` the event envelope (kind, source, payload, caused_by), the event kinds and `EventLog` that saves each input first (its retry waits and give-up, `recover` at start, `sweep` of old handled rows), `runner.py` the only thing that starts a Scout turn, one at a time (Scout speaks first): each event kind carries its urgency, `pick` chooses the next events (a person's words first, then news oldest first), `gate` says whether news may be told now (key, `TAGALONG_QUIET_HOURS`, budget, speech state, idle window, batch window, caps) and `target` the body that answers; news that cannot be told yet stays `new` in the log, and a turn's events end with it or wait again; `presence.py` who is here, what they hear and the sentence break; `Session` builds each turn from the events the runner picks; `Bodies.display_ids` orders the bodies a reply may go to; `tests/test_front_door_routing.py` covers the routing), `timers.py` Scout's timers, `loops/` loops (things left open): shape, store, the mail poll and the surfacing in `service.py`, `tools.py` Scout's loop tools (Show, Done, Later, draft), `triggers/` the pure rules (context, due, urgent, quiet, stale, snooze), `timers_home.py` Home's timers list and cancel tools, `home_tools.py` Home's mail switch, loops list, forget and wipe tools, `reader.py` the mail reader with its pre-filter and own allowance, `source.py` and `sources/gmail.py` the mail source protocol and its Gmail adapter, `bodies_tools.py` Home's bodies status and WhatsApp setup tools, `questions.py` an expert's question to Scout first, `voice/` the mic and speech seam (`VoiceHooks`), the brain's ears (Silero, Moonshine, Smart Turn behind protocols; `stt.py` the speech model list loader and choice over `stt_models.json`, `engines/` one adapter per speech engine; `service.py` is the `VoiceHooks` implementation, one listening session at a time, `load.py` the only importer of the real models, `cuda.py` and `cuda_wheels.json` the NVIDIA libraries fetched on demand (pinned wheels, DLLs into `voice/cuda`, PATH, a one-off child-process probe)) and mouth (`chunker.py` sentences grouped into the chunks the voice speaks whole, `ear_text.py` each sentence rewritten for the ear, `shape.py` each chunk trimmed, faded and followed by a gap, `mouth.py` the one-worker chunk queue (a spoken reply goes out as `speech` frames, one per chunk; pause, resume and clear), `speakable.py` the sentence rules and splitter, `kokoro.py` the Kokoro adapter, `tts.py` the `Tts` protocol and the voice roster loader over `tts_models.json`, `piper.py` and `supertonic.py` the other two adapters, `tts_engines.py` the engine registry, `stt_choice.py` the saved speech-model choice and the card name, `tts_choice.py` the saved speaking-voice choice (`tts_voice`, a stale id reads as Auto), `tts_tools.py` Home's `tts_state` and `set_tts`, `stt_tools.py` Home's `stt_state` and `set_stt`), `speech_tools.py` the interjection (one short call at a sentence break: `speech_continue` or `speech_replace`, wording in `mind/interjection.md`), `mind/` Scout's soul, `ear.md` (how a read-aloud reply is written: the spoken part, then `---` and the on-screen part), `events.md` (per-kind notes), `approvals.md` (side-check and offer wording), `capabilities.py` (the capability picture in the prompt), prompt, thinking loop (`turn.py`: history stays valid even when a turn is cancelled) and `resume.py` (rebuilds history from the saved chat, joining the per-event rows); `setup/` Scout setting things up: `paths.py` (locations under the home folder), `facts.py` (`inspect` the machine), `net.py` and `registry.py` (ACP and MCP registry read with a cache; MCP search by query and cursor), `trust.py` (who is Official: the service's own reversed domain or a vendor allowlist), `grouping.py` (results per service, Official first), `why.py` with `mind/why_pick.md` (the one-line why-pick for a community app, cached), `node_runtime.py` and `archive.py` (Tagalong's own checked Node, safe extract), `store.py` (installed experts), `events.py` (setup news is an event: the new one is posted, then older waiting ones end), `install.py` and `expert_tools.py` (`install_expert`, `login_expert`), `login.py`, `terminal.py` and `env.py` (expert login, the terminal-window seam, the per-expert env strip), `flights.py` (one sign-in or install flight per expert, with its `signin` or `install` open item: a second request joins it), `tools.py` (`inspect_machine`, `find_experts`, `find_apps`, the `hand_off` refusal facts), `apps.py` (`install_app`: a registry app saved like `add_app`), `updates.py` (newer versions of installed experts and apps, the daily check, applied never mid-job), `home_tools.py` (Home's setup tools for the Connections page and the tour); `cli.py` the `tagalong` command (doctor, key set, install, apps add, login, stop, pair, service, serve, update) over `setup/`; see docs/brain/README.md)
